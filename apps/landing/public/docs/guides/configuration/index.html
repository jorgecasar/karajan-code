Config File Location

Section titled “Config File Location”
File Purpose
~/.karajan/kj.config.yml Main configuration
<project>/.karajan/kj.config.yml Project-level overrides
<project>/.karajan.yml Project pricing overrides only

Override priority: CLI flags > project config > global config > defaults.

Since v1.57.1, the YAML config loader tolerates duplicated keys in user config files. If a key appears more than once, the last value wins without raising an error.

Budget Tracking (Estimated)

Section titled “Budget Tracking (Estimated)”

Karajan adds no extra cost — it runs CLI agents (Claude Code, Codex, etc.) under your existing subscriptions. The budget system tracks tokens and estimates what the session would cost if you were using APIs directly, based on published pricing rates. This is useful for comparing approaches and setting guardrails, not for billing.

Model/Provider Resolution (v1.57.2+)

Section titled “Model/Provider Resolution (v1.57.2+)”

When the model field uses a prefixed format like gemini/pro, Karajan automatically infers the provider from the prefix and strips it from the model name. For example, model: "gemini/pro" resolves to provider: gemini, model: pro. If a provider is set explicitly and the model prefix conflicts (e.g., provider: claude with model: gemini/pro), the incompatible model is dropped and the provider’s default model is used instead. This makes configuration more forgiving and reduces misconfiguration errors.

Model Routing per HU

Section titled “Model Routing per HU”

When a task runs as several HUs, each HU’s coder runs on the model its tier calls for, so simple HUs don’t pay for the most capable model. The tier comes from the decomposition: the number of acceptance criteria, sensitive zones (auth, secrets, migrations, security) and the planner’s own judgement; the higher one wins.

HU tier First iteration (claude) After a failed iteration
trivial haiku, effort low opus, effort max
standard sonnet, effort medium opus, effort max
deep the usual model opus, effort max

kj plan writes each HU’s coder_model from its tier, and you can change it on the HU Board: the run uses yours. Only the coder is routed; the reviewer and Solomon keep their model. A model you chose always wins (roles.coder.model, --coder-model, model_profile, model_routing.fixed.coder). Effort applies to claude only.

by_provider names model levels, not tiers: a trivial HU uses trivial, a standard one medium, and a climb after a failure complex.

kj report shows, per coder model, cost and first-time failures, and how many HUs were routed and how many climbed to the top model, so you can tell whether routing pays off.

Section titled “Language (i18n)”

Telemetry

Section titled “Telemetry”

Karajan collects anonymous usage statistics (version, OS, command, pipeline duration, success rate) to help improve the tool. No task descriptions, code, or personal information is collected. Telemetry is enabled by default.

Or via environment variable: KJ_TELEMETRY=false.

Environment Variables

Section titled “Environment Variables”
Variable Purpose
KJ_HOME Override config/sessions directory (default: ~/.karajan)
KJ_SONAR_TOKEN SonarQube authentication token
KJ_SONAR_ADMIN_USER SonarQube admin username
KJ_SONAR_ADMIN_PASSWORD SonarQube admin password
KJ_SONAR_PROJECT_KEY Override SonarQube project key
HU_BOARD_TOKEN Bearer token for HU Board authentication
KJ_TELEMETRY Set to false to disable telemetry
VISUAL / EDITOR Editor for kj config --edit

Environment variables take precedence over config file values.
