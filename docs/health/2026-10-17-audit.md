## Where the problem is

It is concentrated, not spread out:

1. **The Sentinel.** `src/harden/sentinel-hooks.js` is 1,484 lines written inside a template string, so ESLint and Sonar never analyse it. It took 42 fix commits in 30 days, its shell reader 10 more (the next file took 9). Most fixes answered a false positive with one more exception, which is how it keeps growing.
2. **Seven god functions** (cyclomatic complexity): `planGenerateImpl` 166, `policyCommand` 136, `reviewGateCommand` 134, `buildAuditPrompt` 121, `hardenCommand` 103, `runPreLoopStages` 100, `huCommand` 99.
3. **The way of working.** The machine's `kj` ran from the tree being edited, so a half-made edit became a field bug (#2230). Fixed by KJC-TSK-1080 (stable clone of `main`).

## What is fine

Architecture (one short import cycle, `sonar/manager` ↔ `sonar/discovery`), duplication and tests. The critical alerts of `kj audit` are in dependencies, not in our code.

## Outside our code

235 open vulnerabilities in dependencies, 9 critical (vitest/tinypool, proxy-addr, astro in the landing, next in radar); a hardcoded bcrypt hash in a radar migration; CI actions not pinned to a SHA; 7 unused dependencies (helmet and express-rate-limit among them); generated docs (`apps/landing/public/docs`) versioned in the tree.

## Plan (agreed with the user)

1. Process: the machine's `kj` follows a stable clone of `main` (KJC-TSK-1080, done) and the two critical Sonar bugs (KJC-BUG-0372).
2. ADR to redesign the Sentinel: real, tested modules instead of a template string, and a shell parser instead of regexes with exceptions (KJC-TSK-1081).
3. Split the seven god functions, one PR each.
4. Critical dependencies and an OSV gate in CI (KJC-TSK-1082).
